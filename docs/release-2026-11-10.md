# EGZ studio release review — 10 November 2026

This release combines the original 3D landing and bounded splash, cursor-responsive
decorations, five mascot-led tutorials, the Mini Playground photo frame, and free
local original-PNG export without login or watermark. New captures remain local;
the public studio does not request account sessions or upload photographs. Existing
private account/admin routes retain authentication and MFA requirements.

## Publication boundary

Only maintained source, tests, public configuration, original artwork/video assets,
and regeneration tooling are included. The static build copies an explicit
allowlist into a fresh `dist/`. Credentials, environment files, photographs,
datasets/models trained locally, screenshots, traces, raw audit reports, scanner
binaries and dependency directories are excluded. The new media contains original
EGZ characters and synthetic examples, not visitor photographs.

## Findings and fixes

- The privacy notice incorrectly said withdrawing cloud consent did not delete
  existing copies. It now matches the database: withdrawal closes access and
  schedules cloud deletion. Adjacent account notices explain that consequence.
- Database migration verification depended on Windows/Linux line endings.
  Checksums now recognize historical LF/CRLF variants and store new hashes with
  LF normalization; SQL-content changes still fail validation. No migration was
  edited or applied during this release review.
- The local Python environment contained advisory-affected Pillow, certifi and
  pip versions. Dependency floors require Pillow 13+, certifi 2026.10.18+, and CI
  installs pip 26.2+. The local packages were updated and the exact installed
  inventory was re-audited. See the upstream
  [Pillow advisory](https://github.com/advisories/GHSA-4558-3h8r-v8xp),
  [certifi advisory](https://github.com/advisories/GHSA-6q48-6c7w-9gw2), and
  [pip advisory](https://github.com/advisories/GHSA-qwm4-qh6w-59xr).
- GitHub Actions are pinned to verified upstream commit SHAs. CI also audits the
  isolated tutorial tooling and Python environment and checks tutorial scene state.
  Workflow permissions remain read-only and npm lifecycle scripts remain disabled.

No application cross-principal exploit was established by the source reviews.
This does not establish that no vulnerability exists.

## Verification

- [Gitleaks 8.30.1](https://github.com/gitleaks/gitleaks), downloaded from the
  official release with its checksum verified: available Git history scan clean.
  The staged release is scanned separately before push.
- npm audits of the root and tutorial package: zero known vulnerabilities.
- [pip-audit 2.10.1](https://github.com/pypa/pip-audit) of the exact updated local
  Python inventory: zero known vulnerabilities. Fresh dependency resolution is
  checked on Linux CI; Windows ARM requirements resolution hit an OpenCV/path
  limitation and is not represented as a successful requirements audit.
- Local checks passed: 32 Node regressions (31 existing plus the new migration
  checksum case), 25 Python tests, 64 browser scenarios and 600 tutorial scene
  states. Three CI jobs gate the release again on Linux.
  Browser coverage includes actual local MP4 decoding, camera/3D lifecycle,
  PNG byte equality, owner/profile separation, missing assets and recovery.
- Owner observations used a read-only database transaction: all six application
  tables have RLS, the PNG bucket is private with a 3 MiB limit, seven privileged
  RPCs deny anon/authenticated execution, four applied migration hashes match
  source modulo LF/CRLF, and retention runs every five minutes. The latest three
  observed retention executions succeeded. No photographs were read or changed.
- Hosting environment metadata showed production-only contexts for the required
  keys, with no production secret context shared with previews. Provider signup
  is disabled and email confirmation remains required. Existing free-plan scope
  limitations and administrator visibility of environment values remain as
  previously accepted; see [deployment notes](deploy-netlify.md).
- GitHub had no open issues at review time. Existing major dependency PRs were
  inspected without automatically merging them into this feature release.

## Limits

The formal `security-audit` run is **incomplete**, not a full pentest: its strict
OS sandbox and no-follow/nonblocking validator protections are unavailable on the
Windows host. Four read-only reconnaissance reviews and an independent focused
review were performed; their raw records remain outside Git. No clean/full
coverage claim is made. Strix/Docker, destructive production tests, availability
attacks, paid scans, physical-device calibration and physical printing were not
run. Applied-provider observations and ordinary release regression tests are
separate from that incomplete source-audit workflow.

Post-deployment acceptance must verify the exact published commit, HTTPS/headers,
private-path exclusion, anonymous API denials, guest camera/export, new assets and
responsive behavior. This report is a release review, not a guarantee against all
cyberattacks. Shared browser profiles intentionally share the local guest gallery.
