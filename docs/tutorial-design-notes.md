# Tutorial video and copy decisions

30 October 2026. Scope: concise product copy and local, original 3D tutorials for menu selection, hand effects, Painting, Photobooth and Meme. No administration, login or account tutorials.

## Decisions and evidence

- Render the tutorial scenes once into silent MP4s. Remotion supports frame-driven Three.js scenes through [`ThreeCanvas`](https://www.remotion.dev/docs/three-canvas), and [`renderMedia`](https://www.remotion.dev/docs/renderer/render-media) exports the compositions. The tutorial player uses native video; its rendering dependencies stay in the isolated local tool. The separate live landing scene now also uses Three.js and releases it before camera processing starts.
- Load a clip only when the tutorial opens. Use muted inline playback, native pause/seek controls and a poster. A denied autoplay request leaves Play available. This follows [MDN's video element guidance](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video) and [autoplay guidance](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay). Reduced-motion users see a paused poster and can explicitly play.
- Use a centered native dialog with a visible close button, Escape dismissal, focus inside the modal and focus restoration after closing, following the [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).
- Auto tutorials default on when first entering the menu and when selecting a different mode. The switch persists only a local `on`/`off` setting. Manual access remains available when auto tutorials are disabled. Blocked storage falls back to the current tab's preference.
- Each 12-second video has four selectable chapters. The matching instruction is also readable outside the video, with local WebVTT captions available. Media failure never removes Skip or the chapter instructions.
- While a tutorial is open, existing modal boundaries stop painting, keyboard capture and automatic fist capture. After closing a Photobooth tutorial, the fist must be released before gesture capture is rearmed. An active photo session cannot be interrupted by a tutorial.
- Keep actionable errors and meaningful consent text. Shorten repeated promotional and explanatory copy. Cloud consent still states 30 days, admin access, no retrospective upload, and no publication or AI-training permission.

The studio has no bottom control bar. Privacy Policy is an underlined text link. Gesture calibration remains the primary entry; M opens keyboard mode selection, S captures, X stops the camera, R retries a retained export, and Escape cancels an active photo sequence. These shortcuts are also available to screen readers through the workspace description. Tutorial chapters and captions do not point to removed controls.

## Local production assets

Five original scenes, modeled with primitive meshes; no camera footage, external models, voice services or remote fonts. The generated MP4s, posters and captions are explicit entries in the static build allowlist. Render sources, the tool dependency lockfile and `web/tutorials/manifest.json` make regeneration inspectable. The rendering tool overrides Zod to the patched 4.6.7 version; root application dependencies are unchanged.

## Research limits

Focused technical research addressed three questions: frame-driven 3D rendering, browser video loading/playback, and accessible modal behavior. Four official documentation sources were read, with MDN's autoplay guide as an additional reference. Exa/Firecrawl tools were unavailable; official documentation was accessed with the available web tool. Confidence is high for the documented API and modal behavior, while responsive fit and gesture correctness require the repository's browser tests and rendered review rather than documentation alone.

## 9 November 2026: mascot-led 3D revamp

All five tutorials now share the original lime spark guide used on the landing page. Rounded extruded controls, a stage, actual 3D finger joints, subtle camera movement and shadows establish depth. A second mascot demonstrates facial expressions; synthetic mascot portraits illustrate photo results. No admin, login or account tutorials were added. The existing skip, chapter navigation, automatic-tutorial preference and reduced-motion poster behavior remain.

The implementation reuses installed tools rather than adding another animation engine or downloading a character with unrelated licensing. The import-free mascot factory takes its host's Three.js namespace because the landing and authoring packages use different pinned versions. This follows React Three Fiber's [object ownership guidance](https://r3f.docs.pmnd.rs/api/objects): the scene is created per composition and its geometries, materials and textures are explicitly disposed.

The technical basis is Remotion's [ThreeCanvas](https://www.remotion.dev/docs/three-canvas), [still rendering](https://www.remotion.dev/docs/renderer/render-still), and [media rendering](https://www.remotion.dev/docs/renderer/render-media), plus Three.js [PBR materials](https://threejs.org/docs/pages/MeshStandardMaterial.html), [perspective cameras](https://threejs.org/docs/pages/PerspectiveCamera.html), [shadows](https://threejs.org/manual/pages/shadows.html), [world transforms](https://threejs.org/docs/pages/Object3D.html), and [bounds](https://threejs.org/docs/pages/Box3.html). Review of the pinned [Remotion license](https://github.com/remotion-dev/remotion/blob/v4.0.539/LICENSE.md) confirmed it has its own terms, rather than MIT. These primary sources support the implementation choices; visual quality was assessed from rendered chapter stills, not inferred from documentation.

Content was checked against the actual gesture handlers. Painting shows two diagonally separated pinches and releases one while both hands remain visible. Photobooth's compressed sequence explicitly says “Demo dipercepat”; the real application retains three 3-second countdowns. Opposing L hands show mosaic and both downward L hands show rotation. Geometry inspection samples 600 frame states, including fingertip contact, all L orientations, connected 3D finger segments, visible bounds and deterministic seeking. The first visual pass caught a portrait sitting behind its beveled frame; depth was corrected and now has an assertion. Inspection is of the actual Three.js rig, not Blender/bpy: there is no `.blend` asset or armature in this workflow.

Output remains five silent 12-second 960 × 540 MP4s with JPEG posters and synchronized VTT captions, now at 30 fps. Local chapter stills and transform evidence live under ignored `docs/ui-preview/tutorial-revamp/`. No camera footage, external models, speech service or remote runtime assets are involved. Browser playback and gesture calibration on physical devices remain separate checks from the offline scene inspection.

Local verification completed on 10 November 2026: all five encoded H.264 clips have 360 frames, 12 seconds, no audio stream, and matching manifest SHA-256 hashes; combined MP4 size is 1,080,335 bytes. All 31 Node tests, seven tutorial browser tests and seven landing browser tests passed. Tutorial checks covered actual media decoding, seeking, local-only requests, stopped playback on close, skip/Escape, persistence and denied storage, failed-media recovery, capture isolation, focus containment and six viewport sizes. Desktop and mobile dialog screenshots were captured from the normal local server on port 4173. Tool dependency audit reported zero vulnerabilities; the available local Git/source audit found zero secrets or private paths, excluding binary/oversized blobs as reported by the scanner. This is local verification, not a production deployment or a physical-camera calibration.
